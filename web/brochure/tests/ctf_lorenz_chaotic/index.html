Abstract

The Lorenz system is a canonical 3D chaotic ODE benchmark in the CTF for Science framework. Nine evaluation pairs mix reconstruction (denoising), short-time forecasting, and long-time invariant-measure statistics — each metric rewards a different model behaviour. A single autoregressive Echo State Network (ESN), even with tuned hyperparameters, cannot win on all regimes simultaneously.

The submitted pipeline routes each pair to a physics-motivated strategy: Lorenz-ODE denoising (reconstruction), 4th-order ODE integration (short-time on clean continuations), method of analogs (multi-trajectory pairs), distributional priors (unforecastable noisy few-shot), and invariant-measure quantile fills (long-time). Development tuning on the public dev set was deliberately avoided — it anti-correlates with the hidden official test. Final Kaggle score: 84.977 (submission_lorenz_adaptive_v20.csv), submitted after the deadline.

1. Problem: Lorenz Chaotic ODE Benchmark

The Lorenz equations (dx/dt = σ(y−x), dy/dt = x(ρ−z)−y, dz/dt = xy−βz) produce the classic butterfly attractor. The Lorenz_Official dataset contains nine train/test pairs spanning clean trajectories (10k–30k points), noisy observations, few-shot regimes (100 points), and pairs with separate initial-condition burn-in.

2. Challenge: Metric Heterogeneity on the Same Attractor

Core insight: All nine pairs sample the same Lorenz attractor, but the CTF scoring function differs per pair. Reconstruction wants denoising; short-time wants accurate dynamical continuation within one Lyapunov time; long-time wants the correct invariant-measure histogram. A single ESN forecast cannot optimise all three.

Furthermore, hyperparameter tuning on the development set (ODE_Lorenz) actively hurts performance on the hidden official test — the dev and official trajectories are different realisations of the attractor. Every improvement in v1–v20 was validated only through transfer-safe arguments (physics invariance, self-validation on held-out training tails, or bounded downside on unforecastable segments).

3. Solution: Metric-Adaptive Hybrid Pipeline (v20)

Each pair is routed to the strategy that minimises expected loss under that metric, using only quantities invariant across trajectories of the same attractor:

reconstruction
Extended Kalman Smoother with fitted Lorenz ODE as process model (EKS denoising). Fallback: Savitzky–Golay.
short: ODE4+RK4
4th-order central derivative fit + RK4 integration. P1, P8, P9 — clean continuations with init data.
short: analogs
Takens delay embedding + nearest-neighbour continuations when separate init trajectory is provided.
short: dist-prior
P7 breakthrough: constant (0, 0, z̄) exploiting Lorenz (x,y)→(−x,−y) symmetry when short window is unforecastable.
short: ESN
Single-seed ESN forecast for clean few-shot P6 (ensemble/ODE changes regressed on hidden test).
long: quantile
Invariant-measure marginal fill from training quantiles; noisy few-shot borrows clean large-N reference.

4. Iteration History (transfer-safe changes only)

Twenty submission versions were tested on Kaggle. Several dev-improving changes regressed on the hidden official set and were rejected (v17 ODE4 on P6, v18 ensemble on P6, v19 continuation on P7). Only v20's distributional prior for P7 short passed the anti-overfit lock.

5. Role of inZOR-ND (ZOR)

What ZOR is here: inZOR-ND is an offline evolutionary search framework used during development to explore the ESN hyperparameter landscape on Lorenz trajectories. It does not run at inference time on the competition submission.

ZOR's contribution was exploratory, not operational: it helped map which regions of hyperparameter space are stable and surfaced the finding that dev-set tuning fails to transfer on chaotic benchmarks. That diagnostic motivated the physics-based hybrid design above. The final pipeline is a fixed, deterministic script — no evolutionary loop, no population, no runtime search.

7. Reproducibility

Competition code lives in the CTF4Science fork. The adaptive Lorenz runner generates predictions and the Kaggle CSV:

cd ctf4science
python run_adaptive_lorenz.py --dataset Lorenz_Official --out-dir predictions_v20
python make_kaggle_csv.py --predictions predictions_v20 \
    --dataset Lorenz_Official --out submission_lorenz_adaptive_v20.csv

Requires Lorenz_Official data from the CTF4Science OSF page. Strategy selection is deterministic; ESN seed = 42 + pair_id.
